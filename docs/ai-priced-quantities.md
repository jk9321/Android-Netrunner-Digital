## Corp ports (src/ai/corpPorts.ts, Stage B review R8)
The one seam through which the valuation layer and prompts.ts reach a Corp owner. `corpAI.ts` fills it once as it loads (`registerCorpPorts`), and an unset port throws. The ports are readers of the owners, not copies, and are not counted as duplicates. There are exactly four: `keep` and `holdingRezIds` (corp/rezMoney.ts; valueModel boardNeed, iceValues rezBudget), `perfectRecallTarget` (corp/rez.ts; prompts.ts), and `freeInstallTarget` (the ranking's install choice, corpAI.ts; prompts.ts). Stage D3 deletes `freeInstallTarget`'s port when the prompts read `place`. The board-only helpers `mainRemote` and `withIceInstalled` live in the leaf `src/ai/board.ts`. Guards (tests/codeHealth.test.ts): corp/ is in no value-import cycle; the largest cycle in src/ai is at most 16 modules (29 before R8, 27 at beta 545f146); outside corp/, only corpAI, search, index, incomeLine (knownIncome) and rezModel (corp/pools) import it; the ports are these four.

## How to use
- Writing a spec: list the rows the new code reads. If it needs a quantity that is not here, add the row and the owner in the same branch.
- Reviewing: grep the diff for a new computation of any row (new helper that sums rez costs, counts ice against a rig, or derives agenda odds). One found is "Changes needed".
- Fixing a row: lower the count and name the commit in "Fixed in". At 1, write "single".
